# ZC001-P `layout-padding-mismatch`

warn · likely · ZC (zero-copy layout)

A `#[repr(C)]` `ShankAccount` or `ShankType` struct whose in-memory layout has padding, so it differs from its packed borsh layout. On-chain zero-copy reads and the generated borsh client then disagree on where each field is.

## What counts

- **Measured:** structs whose fields are primitives, fixed arrays, or 32-byte keys (`Address`/`Pubkey`).
- **Skipped:** a struct with a nested or foreign-typed field.
- **Shared analysis:** the same analysis gives the padding warning in `pinoc build` and `pinoc idl`.
- **Why `warn`:** it only matters to the generated borsh client; a program driven another way is unaffected.

## Fix

Add explicit `_padding: [u8; N]` fields so both layouts agree, or reorder fields largest first. Promote it with `--deny ZC001-P`.

## Flagged

```rust
#[repr(C)]
#[derive(ShankAccount)]
pub struct Vault {
    pub bump: u8,
    pub amount: u64,
}
```

## Not flagged

```rust
#[repr(C)]
#[derive(ShankAccount)]
pub struct Vault {
    pub amount: u64,
    pub bump: u8,
    pub _padding: [u8; 7],
}
```
